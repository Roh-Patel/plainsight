# Plainsight: decisions and results log

This log records every choice later code depends on (models, hyperparameters, seeds, thresholds, paths) and every metric quoted publicly (with date and run ID). Evaluation rules were written down before the data that tests them was seen. Changed decisions are edited in place, so each entry is the current one. IDs are stable but not contiguous: superseded and merged entries were removed.

## Decisions

### Project rules
- **D006** Raw full text stays local. The public demo shows short snippets with arXiv links. *Why:* per-paper licensing varies.
- **D059** (2026-11-16) No deadlines. No task is dropped, shortened or reordered for time, including T18. Evaluation rigor unchanged: pre-declare metrics, never tune on the 133 eval questions. Cost and data limits still apply. *Why:* my decision. T18 is required for the six-system ablation.
- **D060** (2026-11-17) Seventh system `dense_ft`: fine-tuned embedder alone, dense-only search over checkpoint-810, top 100. Main ladder (6 systems): bm25, dense_base, hybrid_base, hybrid_base_rerank_base, hybrid_ft_embed, hybrid_ft_embed_rerank_ft. The D029 comparisons are the five adjacent steps plus dense_base to dense_ft, Holm over six. D036 pools all seven systems. *Why:* hybrid_ft_embed keeps the base BM25, so fusion can absorb the embedder's effect. T22 needs the embedder isolated.

### Corpus and ingestion
- **D001** arXiv astro-ph.EP, v1 date 2024-01-01 or later, exoplanet and planetary topics, about 3,000 papers with arXiv HTML, snapshot 2026-10-18. Full-text passages, not abstracts. *Why:* clean HTML full text, rich learner questions. Abstract-only retrieval is too easy to show a fine-tuning gain.
- **D008** Fetch validity (`is_article`): at least 3 `ltx_para` elements. `bad_html` means a build-failure stub, not a missing-structure document. *Why:* a size test passed a stub, and a test requiring an abstract or section wrongly removed 9 of 10 real documents (white papers, short papers; refetched). Validated against one stub only. Lowest paragraph count among kept papers is 5.
- **D009** Fetch order: seed 0 over sorted candidate IDs, 3.0 s delay, resumable. Target 3,000 ok plus 9 reopened papers = 3,009.
- **D011** Parse unit: any `section.ltx_{part,chapter,section,subsection,subsubsection,paragraph,subparagraph,appendix}`. Title is a breadcrumb of stripped headings joined by " > " ("Appendix: " prefix for appendices). Text outside any heading is a unit with an empty title. Title and abstract come from metadata only. *Why:* `ltx_section` is absent in 17 files, heading tags are unreliable, and the HTML has no abstract in 79 files, so level comes from element nesting.
- **D012** Drop display equations, footnotes, `ltx_ERROR`, parenthetical citations, figures and tables (with captions), acknowledgements and bibliography. Convert inline math with the MathML converter. Textual citations ("Snellen & Brown (2018)") stay for grammar. *Why:* dropped items are unreadable or break sentences. Figure and table loss is a known v1 limitation.
- **D013** Drop sections by exact normalised title: references, bibliography, acknowledg(e)ments, abstract, author contributions, competing interests, funding, data and code availability, declarations, disclosures, AI-use declaration and their variants. The parser logs every kept and dropped title. *Why:* boilerplate can never be gold. Keyword matching also hit real sections ("statement of need", "problem statement", "code testing").
- **D014** Drop 2401.02195 (font-map garble across about 44% of text, garble ratio 0.32 against a corpus maximum of 0.0003). Result: 3,008 parsed papers.

### Chunking and split
- **D015** Chunker v1. bge-base tokenizer. Body maximum 400 tokens. The 250-token figure is a target, not a floor, and chunks never span sections. Units under 50 tokens are dropped, units of 50 to 150 stay standalone. Greedy paragraph packing. Paragraphs over 400 tokens are split at sentence boundaries (regex guarding et al., Fig., Eq., Sect., e.g., i.e.). A single sentence over 400 tokens is hard-split by tokens. Overlap is the last 1 to 2 sentences, up to 50 tokens, within the same unit only. `chunk_idx` is assigned before filtering. *Why:* 25% of 51,194 units are under 250 tokens (median 483), so a floor needs merging across sections, which the passage_id scheme forbids. Maximum prefix is 102 tokens, so 400 + 102 + 2 fits 512.
- **D017** Junk filters, run in this order, thresholds final for v1: (1) missing_spaces: fewer than 1 whitespace per 12 characters. (2) long_letter_runs: 3 or more runs of 25+ letters. (3) low_function_words: under 10% English function words (50-word list `STOP` in ingest/chunk.py; also drops non-English). (4) table_residue: over 30% of words contain no letter, only if function-word fraction is below 0.25. (5) comma_density: over 1 comma per 4 words, only if the fraction is below 0.25. Result: 428 dropped, 116,356 kept. *Why:* a non-letter wordpiece rule cannot separate tables from numeric prose. Function-word fraction can (kept median 0.371, 1st percentile 0.25).
- **D018** Split by paper (prevents train/test leakage), seed 0, ratios 70/10/20, `random.Random(0)` over sorted IDs of the 3,008 papers with passages: 2,106 train, 301 val, 601 test. Frozen. `ingest/split.py` refuses to overwrite without `--force`, and rebuilding invalidates everything from T13 onward.

### Indexing and retrieval
- **D019** Baseline embedder BAAI/bge-base-en-v1.5. Passages embedded from `embed_text` with no prefix. Queries always get QUERY_PREFIX ("Represent this sentence for searching relevant passages: ", in ingest/dense.py), at T11 and in fine-tuning. fp16 forward pass, fp32 normalisation, fp16 storage. Fine-tuned indexes use the same precision. *Why:* a prefix or precision mismatch would inflate the measured gain.
- **D020** BM25 indexes `embed_text`. bm25s defaults (lucene, k1 1.5, b 0.75), English stopwords, PyStemmer, default token regex, no query prefix, no tuning before T21. *Why:* the ablation compares methods, and tuning on the eval questions would favour BM25 against the fine-tuned system. Single-character tokens and M_⊙-style math are lost, a candidate for the T30 acronym and numeric analysis.
- **D021** Qdrant 1.20.0 in Docker (volume `qdrant_storage`, bound to 127.0.0.1:6333). Collections `passages_dense_base` and `passages_dense_ft`, cosine. Point ID is the line index in `passages.jsonl`. Payload holds `passage_id` and `paper_id` only. Eval runs use `exact=True`. *Why:* exact search keeps HNSW approximation out of the numbers. The T28 compose file must not publish 6333 beyond localhost.
- **D022** Numpy dense backend: fp16 matrix on the GPU, upcast to fp32 and re-normalised row by row, fp32 scores against an fp32 normalised query, ties by lower point ID. Used for T14 and T15 bulk search. Qdrant serves the app and the eval harness. *Why:* fp16 rows have norm 1.0 ± 0.0002. Without re-normalising, only 78% of 50 queries matched Qdrant's top-10 order. With it, top-100 overlap 1.0000 and identical order for 50 of 50.
- **D023** Hybrid (RRF): BM25 top 100 and dense top 100, equal weights, k = 60, truncated to 100, ties by lower point ID. No tuning. Code in `retrieval/`. *Why:* k = 60 is the original default. Fixed before any eval question existed.
- **D024** Reranker (systems 4 and 6): BAAI/bge-reranker-base, fp16, raw logits as `score`. Reranks the top 50 of the fused list. Input is `text`, not `embed_text`: pair input, truncation `only_second`, max_length 512. T18 trains on the same input format. *Why:* the XLM-R tokenizer overflows 23.39% of `embed_text` against 6.08% of `text` (444-token passage budget), and `text` is what is shown and cited. Depth 50 matches the T15 mining range and the app's latency budget.
- **D025** Reranker ties keep the incoming fused order. Queries are capped at 128 tokens before scoring and counted in `Reranker.stats["query_truncated"]`. *Why:* logits are fp16 so ties occur, and RRF already ordered them. One over-long synthetic query must not kill the T15 scoring run.
- **D035** Baseline and fine-tuned runs (`eval/make_runs.py`, `eval/make_runs_ft.py`) refuse to overwrite `runs/*.jsonl` without `--force`, and `--force` is not allowed once T19 starts. `--limit` runs may not write to `runs/` (dry runs go to gitignored `scratch_runs/`). Systems use the Qdrant backend with `exact=True`. One fused search per question is reused for hybrid_base and the reranker input. Queries are encoded in batches of 64. W&B is skipped for T11 and metrics go there at T21. *Why:* pool and qrels derive from these files. Dense scores drift about 1e-5 across batch compositions, which can flip near-ties.

### Evaluation design
- **D005** Hand-built test set (133 questions, D031 to D033). Labels by pooling, LLM pre-grade and human review. *Why:* synthetic-only evaluation can inflate gains.
- **D028** Metrics, fixed before any label existed. nDCG gain 2^g - 1 (grades 0, 1, 2 give 0, 1, 3), ideal DCG over all judged passages of the question, top 10. Unjudged counts as grade 0. Rank is list position, never score. Recall@k, MRR@10 and paper_hit@10 use grade >= 2 as primary, grade >= 1 in an appendix table. `paper_hit@10` is 1 if any top-10 passage is from a paper with a relevant passage. A question with no relevant passage at the threshold raises an error and is never scored 0. Recall is pooled recall (against judged passages) and the README must say so. nDCG@10 is the single pre-declared primary metric. `judged@10` and `judged@20` are reported per system. *Why:* one primary metric limits multiple comparisons, and judged@k shows how much of each top 10 and top 20 was labelled.
- **D029** Statistics (built at T21): percentile bootstrap over questions, 10,000 resamples, seed 0. Paired differences reuse the same resample indices. Comparisons fixed in advance (see D060), Holm over six. T09 outputs per-query values only.
- **D030** Strict loaders (`eval/loaders.py`): unknown passage IDs, duplicate rows, bad grades, wrong column counts or system names raise. Run and qrels must cover exactly the same qids. Excluding a question is a deliberate decision, never a fallback.
- **D031** Topic list frozen: 43 topics in 12 families (`data/eval/topics.txt`), chosen from title and abstract regex counts per split (`eval/topic_coverage.py`) after a 5-title spot-check. Fixed before any question or label existed. Merges: subsurface oceans into icy moon geophysics, pebble accretion into core accretion, orbital stability into orbital resonances, habitable zones into habitability. The spot-check is crude and the 12 families are judgement, not measured.
- **D032** Allocation: 2 questions per topic, 3 with 10+ test papers, 4 with 25+ test papers. Total 133. *Why:* 2/3 alone gave 117, which T20 attrition would push below 120. The 25 cutoff is arbitrary.
- **D033** Question protocol: written from memory with no passage, paper or system output seen. `style` and `tags` set at write time. `data/eval/questions.jsonl` is written with LF endings, marked `-text` in .gitattributes, and frozen. `eval/validate_questions.py` refuses to overwrite it without `--force`. Any change needs a new decision and a new file. SHA-256 in Notes. The validator thresholds (near-duplicate Jaccard 0.6, style band 25 to 40%, 8 per tag) were provisional and only matter if a new question file is ever created.
- **D034** T22 held-out definition: per-question recall@10 and @20 restricted to grade >= 2 passages in test papers, compared with train-paper gold for the same questions, plus the count of questions with at least one test-paper grade >= 2 passage. "Held-out" means test only, never val. No nDCG restriction. *Why:* val drives T16 checkpoint selection and T26 calibration. Restricted nDCG would penalise valid train-paper hits.
- **D036** T19 pool depth is 10 over all seven systems, fixed before any label existed. The review rule is D066. *Why:* at depth 5 with systems 1 to 4, 28 to 38% of each top 10 was unjudged (judged@10 0.617 to 0.720). D028 scores unjudged as 0, so differences would reflect pool membership. Cost for systems 1 to 4: 3,341 pairs against 1,830.
- **D066** (2026-11-19, declared before any T19 grading call or human label) T19/T20 labelling protocol. Replaces D036's review rule (25% random sample plus every LLM-vs-pool disagreement); D036's pool stands. **Pool:** union of the top 10 of the seven run files per question, deduplicated: 4,770 pairs (mean 35.9 per question, min 23, max 48), counted from run files only. **LLM grading:** `claude-sonnet-5-5` grades every pool pair twice, with two prompt wordings P1 and P2 written and hashed before any call. Both share the grade definitions (0 does not address the question; 1 partially answers it or gives needed background without the answer; 2 answers the question) and the input (question, paper title, section title, passage `text`), one pair per request, no system name, rank or score shown, output a JSON grade with no explanation. The wordings differ in phrasing and example order only. Message Batches API, `max_tokens` 4000, default thinking. A format-only pilot of 20 pool pairs checks parsing and stop reasons; its grades are not read and the prompts are not edited for content after it. A response that fails to parse or stops for any reason other than `end_turn` is resubmitted once; a second failure sends the pair to human review. The cost estimate is approved before submitting. **Human review set**, graded blind (question, title, section and text only; no LLM grade, system or rank), items shuffled with seed 29: (a) a random sample of 250 pairs drawn uniformly from the 4,770 with seed 29 before any grading call; (b) every pair where P1 and P2 differ. A pair in both is graded once. **Final grade:** the human reviewer's where one exists, otherwise the shared P1/P2 grade. **Agreement, on the random sample:** headline is unweighted Cohen's kappa between the human reviewer and the LLM on sample pairs where P1 = P2 (the labels that enter qrels unreviewed). Also reported: reviewer vs P1, reviewer vs P2, P1 vs P2 over the full pool, linearly weighted kappa, raw agreement and the 3x3 confusion table, with 95% percentile bootstrap CIs (10,000 resamples, seed 0, as D029). **Stop rules:** if P1 and P2 disagree on more than 1,000 pairs, stop before any human grading and declare a follow-up entry (only the count is seen). If the headline kappa is below 0.60, stop before T21 and declare a follow-up entry. **Question exclusion:** a question with no grade-2 passage after review is excluded from every table (primary and grade >= 1), logged and counted, never scored 0 (D028). **Files:** `data/eval/label_audit.jsonl` and `data/eval/qrels.tsv` (IDs and grades only, tracked), raw API results in `data/eval/raw/` (gitignored, never deleted). *Why:* a 25% sample (1,193 pairs) plus every disagreement is more than one grader can do carefully. Two wordings catch pairs whose grade depends on phrasing, where LLM errors cluster. Errors the grader makes consistently do not show up as disagreements, so the independent random sample measures them. Sample size 250, the 1,000 cap and the 0.60 floor (the conventional "substantial" band) are judgement calls. The grader sees the title and section prefix while the reranker sees `text` only (D024), so a grade can rest on context the reranker lacked. There is one human reviewer, who also wrote the questions.

### Synthetic queries (T12 to T14)
- **D037** Query prompt v5 (`train/query_prompt.py`). claude-haiku-5-5, no `temperature` (the call rejects it, so sampling is not reproducible), `max_tokens` 4000 (reasoning tokens count against it; at 600, 40 of 50 calls truncated). One call per passage returns one query per voice as JSON, with a `usable: false` escape. *Why:* v1 to v4 failed on form (statements, no question mark, template drift) and content (queries pointing at the passage, copying its mechanism).
- **D038** Sampling filter: train split, `n_tokens >= 100`, function-word fraction >= 0.15 (78,042 eligible passages in 2,106 papers). *Why:* a 60-token passage cannot support three distinct questions, and the 0.10 to 0.15 band was mostly references and affiliations.
- **D039** T12 acceptance, fresh-50 run of v5 unchanged (132 queries, graded by the human reviewer only): A = 0 2.3% (gate at most 5%, pass), **A = 2 75.8% (gate at least 80%, FAIL, accepted by explicit decision after five iterations)**, N = 1 92.4% (pass), V = 1 95.5% / 100% / 95.5% per voice (pass). Further iteration would tune to the sample. The README must say about a quarter of synthetic queries were graded as only partly answered by their source.
- **D040** Rubric changes made after seeing outputs: N criterion ("a learner who has not seen the passage could plausibly type this") added after v2. S (specificity) withdrawn as it cannot be judged from one passage, substitute never built. Usable-rate floor lowered from 85% to 50% because rule 9 makes `usable: false` expected for methods and data passages. Deictic regex stopped flagging "the same" and "such as". Compound-clause check demoted from a gate to a reported rate (dev 9.4%, fresh 3.8%).
- **D042** T13 sample: eligible passages (D038) minus the 100 T12 dev and fresh passages, cap 15 per paper drawn uniformly, seed 14, one global shuffle. Shard 0 is the 500-row pilot, shards 1 to 6 hold 5,000, shard 7 holds 315. 30,815 passages from 2,106 papers. `draw_gen_sample.py` refuses to overwrite, and `--force` is not allowed once a batch is submitted. *Why:* eligible passages per paper have median 34, p90 60, max 355. The cap of 15 is a judgement call, not measured.
- **D043** T13 generation via the Message Batches API, one request per passage, same call as D037 (effort and thinking left at default). `custom_id` is `p` plus the zero-padded point ID. Pilot gates fixed beforehand: zero request errors, non-truncated parse failures under 1%, truncation under 2%. Shards 1 to 7 required shard 0 to pass with the same prompt hash, model and `max_tokens`. Raw results saved verbatim. Outcome: 0 request errors, 0 truncations, max thinking 3,043 tokens. *Why:* capping reasoning would change the generator D039 measured, to save about $8.
- **D044** Rows with no parsed output are dropped and logged with no retry or repair: 36 refusals and 2 parse errors of 30,815 (0.12%). One parse error has a misspelled voice key (`layayperson`), not repaired. Refusals cluster on aerosol, condensing-particle, dust-settling, granular-flow and liposome passages, so those topics are under-represented (README). *Why:* a retry is a second uncontrolled sample, and repairing edits model output.
- **D045** No rank-based drop. Hand check (hybrid_base, 20 per voice x stratum, seed 15, 120 queries, graded blind): A = 2 was 49/60 for source rank above 50 or absent ("out") against 47/60 ("in"), difference +0.033 (95% CI -0.117 to +0.167). N = 1 56/60 vs 54/60. B = 1 12/60 in the out stratum. Pre-registered rule: adopt no drop if out is less than 15 points below in. *Why:* 53.5% of queries have the source outside the top 100. A top-50 drop would cut layperson and half_remembered from 33.3% each to about 24% and 22% and raise confused_undergrad to about 55%, thinning the low-overlap voices the headline claim depends on. Rank marks difficulty, not noise. The test cannot exclude a true gap of about 12 points. B covers only the rank-1 non-source passage in the out stratum.
- **D046** Form filters (`train/apply_filters.py`, regexes imported from `train/form_report.py`), first rule that fires wins, order: banned_phrase, no_question_mark, length, compound_clause, deictic, shared_number, duplicate_text, eval_overlap. Compound clause: drop all 3,484 (10 of 10 two-part questions on the read sample; 3 of 11 dev hits were false positives). Deictic: drop all 279 (27 of 30 sampled hits were fine, accepted for one simple rule). shared_number: drop queries sharing a number of 2+ digits or a decimal with the source, except integers 1500 to 2099 (698 hits). Textbook statistics and ML queries: no filter, accepted (N = 0 was 10/120, 8%, an upper bound). *Why:* form rules carry no rank skew and move voice shares by under 1 point. A copied value is a lexical anchor (src@50 layperson 0.543 flagged vs 0.281). The year exemption is imperfect ("2000 K" passes, "100 days" is dropped).
- **D047** Duplicates and eval overlap. Exact normalised duplicate text across passages: keep the first, drop 18. No embedding near-duplicate drop. Eval overlap: drop synthetic queries with dense_base cosine >= 0.85 (with QUERY_PREFIX) to any of the 133 eval questions (66 hits, 61 as first rule). The cutoff is below the lowest of 13 hand-read paraphrases among the 20 closest pairs (0.868). Audit in `eval_overlap.jsonl`. Final: 69,317 of 73,767 kept (23,639 / 22,973 / 22,705 layperson / confused_undergrad / half_remembered_term). Seeds 15, 16, 17. *Why:* 73% of queries at 0.90+ similarity are layperson, so a similarity drop would shift the voice mix to fix a rare collision. Near-duplicates are handled at T15 by excluding their source passages. The cutoff is partial: paraphrases below 0.85 remain, and 22 of 133 eval questions have a synthetic query at 0.85+ (eval-0008, eval-0096 and eval-0001 hold 30 of the 66). D034 is the control for passage-level leakage.

### Hard negatives (T15)
- **D048** Pool: hybrid_base ranks 10 to 50 from the saved top 100 (D045), kept queries only. Exclude a candidate if it is not a train-split paper, is the source passage, is from the source paper, or is the source passage of any other query (kept or dropped) at dense_base query-to-query cosine >= 0.80. Queries are never dropped for having few negatives. *Why:* val and test text as negatives would break D034. Chunk overlap and `chunk_idx` gaps make adjacent-chunk exclusion unclean. 47.2% of kept queries have a neighbour at 0.80. The 0.80 threshold was not validated.
- **D049** All 1,913,454 pool candidates and 69,317 positives scored with bge-reranker-base (D024, D025), batch size 32, saved to `hn_scored.jsonl`. *Why:* 492 pairs/s at batch 32 (46 at batch 128, cause not investigated). Keeping all scores lets T18 re-filter and thresholds change without re-scoring.
- **D050** Drop a candidate if its logit is above -6, all voices. Path: a margin rule on the positive's logit was dropped (unreliable for layperson and half_remembered), a pre-registered pool rule gave t = 0, the first hand check moved it to -5, a pooled sweep over 240 graded negatives moved it to -6. Deviations from my own pre-registered rules: no voice-specific fallback for confused_undergrad, pool floor waived for that voice. *Why:* logit AUC for false negatives 0.765 (95% CI 0.685 to 0.835) pooled; 0.747 layperson, 0.837 confused_undergrad, 0.613 half_remembered (CI 0.387 to 0.821). A stricter cut starves confused_undergrad, but fewer cleaner negatives beat about 30% false negatives, and in-batch negatives remain. The value was chosen on data that also measured the problem, so round 3 was the test.
- **D051** Hand-check protocol: per voice 40 random kept queries with the hardest retained negative (lowest baseline rank), plus 4 source controls, shuffled, label B as in D045, one grader (who also wrote the prompt and rubric). Seeds 20, 22, 23. False-negative rate: round 1 (t = 0) 33/120 = 27.5% (95% CI 20.3 to 36.1%); round 2 (t = -5) 15/120 = 12.5% (7.7 to 19.6%); **round 3 (t = -6) 17/120 = 14.2% (9.0 to 21.5%)**, by voice 6/40, 5/40, 6/40, controls 8/12. Round 3 fell in the pre-registered 10 to 15% band with no voice at 20%+, so the pool is accepted with disclosure. t = -5 and -6 cannot be told apart, and the sweep's predicted gain did not appear (selection optimism). Controls were 11/12, 12/12, 8/12 across rounds, so cross-round rates are confounded by grading consistency. The T21 ablation is the arbiter of whether the noise matters.
- **D052** `hard_negatives.jsonl` was built for T16. T18 reuses the same retained negatives under D061, because the judge-based alternative failed validation (D062). *Why:* the file keeps only candidates the base reranker scores at -6 or below, which are easy for that reranker, so a T18 trained on it carries the circularity this entry originally ruled out. That is accepted and disclosed.

### Embedder fine-tune (T16)
- **D053** Dev set for checkpoint selection: queries for val-split passages with the T13 config (prompt v5, Haiku 5.5, `max_tokens` 4000, Batch API, config hash checked against train shard 0). Val papers only, D038 filter, cap 10 per paper, seed 18: 2,973 passages from 301 papers. 2,332 ok, 634 unusable, 7 refusals, 6,996 queries (val-000001 to val-006996), 6,524 kept (2,234 / 2,150 / 2,140 by voice) from 300 papers. D046 form filters plus exact duplicates within val, no eval-overlap drop. First-rule drops: banned_phrase 1, compound_clause 372, deictic 22, shared_number 77. Cost $1.10 (estimate $1.095). *Why:* selecting on the 133 eval questions would tune on the test set, and a dev set cut from train papers would overlap the hard-negative pool.
- **D054** Dev evaluation (`train/dev_eval.py`): kept val queries against a val-only corpus (all 11,536 val passages), embedder only, one labelled passage per query (its source), ties favour the source. Selection metric is nDCG@10 over all kept val queries, nothing else. MRR@10, recall@10, recall@50 and per-voice figures are reported only. Base model: nDCG@10 0.2440 (layperson 0.1994, confused_undergrad 0.3601, half_remembered 0.1740). Dev measures in-distribution performance on held-out papers, not the headline claim. Other passages that answer a query count as misses, and the corpus is 10x smaller than the real index.
- **D055** Training triples: k = 1 negative per query, drawn uniformly from its retained hard negatives, seed 24. Queries with no retained negative (4,874: 714 / 3,573 / 587) are kept without one. Two datasets: with_negative (64,443 rows) and no_negative (4,874). Chosen negative baseline rank: mean 32.5, min 10, max 50. Max uses of one negative 89. *Why:* dropping no-negative queries would break D048 and skew voices (confused_undergrad is 73.3% of them). The hardest negative carries the 14.2% false-negative rate (D051) and would repeat every epoch. Uniform sampling is a judgement call, not compared with hardest-only.
- **D056** Batching (sentence-transformers 6.2.0): `batch_sampler` NO_DUPLICATES on each dataset of a DatasetDict, `multi_dataset_batch_sampler` PROPORTIONAL, `dataloader_drop_last` True, batch 256. Measured on real triples: 251 + 19 batches, 0 repeated values, coverage 99.7% / 99.8%. Same-paper in-batch candidates per query mean 0.234, 20.4% of queries have at least one (at 128: 0.116 and 10.8%). The pre-declared 10% cutoff for a paper-aware sampler was missed and overridden. *Why:* batch 256 gives more in-batch negatives. A same-paper candidate is a false negative only if it answers the query; at an assumed (unmeasured) 30% relevance about 6% of queries are contaminated, below the hard-negative noise. The cutoff was arbitrary.
- **D057** emb-v1, fixed before the first run: start BAAI/bge-base-en-v1.5, max_seq_length 512, CachedMultipleNegativesRankingLoss scale 50 (temperature 0.02), mini_batch_size 32, hardness_mode off, batch 256, learning rate 2e-5, linear decay, warmup 81 steps, 3 epochs (810 steps), seed 42, fp16, checkpoints every 135 steps (`save_only_model`), W&B project plainsight run emb-v1. Passages are `embed_text` with no prefix, queries carry QUERY_PREFIX. Mini-batch 64 peaks at 13.52 GB and spills into system RAM (227 s/step), 128 runs out of memory, 32 peaks at about 7.5 GB. Scale 50 is the bge value from memory, unverified. Learning rate and epochs are judgement calls with no search.
- **D058** Checkpoint rule, declared before the run: highest overall dev nDCG@10 among the six checkpoints, no retuning, stop and diagnose if all score below base 0.2440. Outcome (810 steps, 5,036 s, 6.2 s/step, peak 7.87 GB, loss 3.146 to 0.862): dev nDCG@10 135 below 270 (value in `emb-v1-135.json`), 270 0.4619, 405 0.4774, 540 0.4843, 675 0.4880, **810 0.4898** (selected; `final` is a copy). Checkpoint-810 per voice 0.4390 / 0.6213 / 0.4105. The best checkpoint is the last, so a longer schedule is untested. Dev numbers are never quoted as results. The 133 eval questions were first run at T17.

### Reranker fine-tune (T18)
- **D061** (2026-11-18) Reranker negatives are the D050 pool: the retained negatives in `hard_negatives.jsonl` (hybrid_base ranks 10 to 50, train papers only, ce_score ≤ -6, D048 near-duplicate exclusion), 764,375 negatives. This is the D062 fallback, taken because the LLM-judge alternative (claude-haiku-5-5, K = 4 candidates per query, reconstructed B rubric) failed its pre-declared validation bar. The circularity named in D052 therefore applies to T18: the negatives are ones the base reranker already scores low, so the signal is weaker than true hard negatives.
